Security

This is a read-only aggregation page with no accounts and no user data. Here is the concrete picture.

Attack surface

ItemStatus
User accounts / sign-inNone
DatabaseNone — read-only cache files only
Persisted user inputNone. The search box filters in page memory
File uploads / rich textNone
Payments / form postsNone
Third-party scriptsOnly the Cloudflare Web Analytics beacon (cookieless). No ads, fonts or other CDN dependencies

No hijackable sessions and no injectable persistent input — that is the main security advantage of a site shaped like this one.

Transport and response headers

The site forces HTTPS and sends the following security headers:

  • Strict-Transport-Security — pins subsequent visits to HTTPS;
  • Content-Security-Policy — same-origin scripts plus the Cloudflare analytics beacon only; no inline script, no framing;
  • X-Content-Type-Options: nosniff — disables MIME sniffing;
  • X-Frame-Options: DENY together with frame-ancestors 'none' — prevents clickjacking;
  • Referrer-Policy: strict-origin-when-cross-origin — no full path leakage on outbound clicks;
  • Permissions-Policy — geolocation, camera, microphone and similar capabilities are disabled.

How data is handled

  • Fetched third-party content is plain data (title, link, source name) and is escaped on render — no HTML injection path;
  • Outbound links always use rel="noopener noreferrer" and open in a new tab;
  • The fetcher and the renderer are separate: an upstream failure degrades the data source, never the page itself.

Reporting a vulnerability

If you find a security issue, email security@trends-world.example with reproduction steps and impact. Please do not disclose it publicly, and do not stress-test or run destructive tests against the site.

  • We will acknowledge receipt within 3 business days;
  • Once confirmed, we aim to fix and publish a note within 90 days (with credit if you wish);
  • This is an independent project: no bug bounty is offered, and good-faith testing will not be pursued.

The machine-readable channel is /.well-known/security.txt.

Out of scope

  • Security issues in third-party sites reached from this one — please contact them directly;
  • Issues requiring physical device access, or relying on end-of-life browsers;
  • General "best practice" suggestions beyond the headers above, unless you can show real impact.
