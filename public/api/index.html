API and data

Everything this site publishes is a static JSON file. No API key, no authentication, no rate limit beyond ordinary caching. The same files feed the website.

Endpoints

PathSizeContents
/data/countries.json 36 KB The 176 places: ISO codes, English and Chinese names, continent, subregion, coordinates, which sources apply.
/data/board.json 228 KB Top topic per country in the current snapshot — enough to render the map without loading every detail file.
/data/details/<ISO>.json ~3 KB Full top-10 list for one country, including search-volume bucket, source label and the original article URL.
/data/global.json 3 KB Cross-border clusters: the same topic topping several countries, each with a slug that maps to /topic/<slug>/.
/data/meta.json < 1 KB Generation time, crawl duration, coverage out of 176, source distribution, list of places that failed.

Example

curl -s https://trends-world.pages.dev/data/details/JP.json | jq '.topics[:3]'

Shape of a topic

{
  "rank": 1,
  "title": "大腸",
  "traffic": "1000+",
  "source": "google-trends",
  "sourceLabel": "Google Trends",
  "url": "https://news.yahoo.co.jp/articles/…",
  "news": [{ "title": "…", "url": "…", "source": "…" }]
}

How to read it without getting it wrong

Sources are not uniform. google-trends means search interest; bing-news means same-day news interest. They are different measures — always say which one you are quoting instead of adding them together.
  • traffic values such as 200+ are source-side buckets, not measurements. Never present them as an exact number of searches.
  • rank is the position within that country's list, not a global score, so two rank-1 topics in different countries are not comparable in size.
  • Cross-border clusters are grouped by headline similarity, not geography — a country can land in a cluster whose wording looks unrelated to its own headline.
  • The snapshot is at most a few hours old. Check /data/meta.json before treating anything as "right now".
  • Country and region names use neutral ISO short forms because the site is read internationally.

MCP server for agents

The repository ships a zero-dependency MCP server so an AI agent can query this data without writing HTTP code. Four read-only tools:

ToolArgumentsReturns
trending_by_countrycountry, limitRanked topics with volume, source and URL
global_pulse–Stories trending in several countries at once
search_countriesqueryMatching countries and their current top topic
snapshot_status–Freshness, coverage, source mix, failures
 
{
  "mcpServers": {
    "trends-world": {
      "command": "node",
      "args": ["/path/to/trends-world/mcp/trends-mcp.mjs"]
    }
  }
}

Set TRENDS_BASE to point the server at a different deployment. A machine-readable summary of this site for language models is at /llms.txt.

Freshness and updates

GitHub Actions rebuilds the snapshot every three hours and redeploys the static site. Files are served with a one-day cache header, so add a query string when you need the newest copy, for example /data/board.json?t=1731680000.

There is no private or rate-limited tier. If you need a guaranteed-fresh feed or a higher-volume feed, run the crawler yourself — it is in the same repository and needs only Node.js.
